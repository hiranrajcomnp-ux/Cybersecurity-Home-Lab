10 / TPM INVESTIGATION

TPM Event Investigation

During laboratory monitoring, the Windows System log generated the following event:

EVENT / TPM-WMI / 1040

TPM Pre-Attestation Health Check

ERROR

Log Name: System

Source: Microsoft-Windows-TPM-WMI

Event ID: 1040

Computer: Vaskar

User: SYSTEM

Date: 29 September 2026

Time: 6:53:45 PM

Referenced diagnostic file:

C:\WINDOWS\Logs\MeasuredBoot\0000000089-0000000000.json

The event reported that pre-attestation health checks identified a critical failed component.

The event alone does not identify the exact failed component or establish that the system was compromised.

15 / LABORATORY FINDINGS

Laboratory Findings

FINDING 01

TPM-WMI Event 1040

DOCUMENTED

Observation: The Windows System log recorded TPM-WMI Event ID 1040 indicating that pre-attestation health checks identified a critical failed component.

Evidence: Measured Boot diagnostic JSON file referenced by the event.

Assessment: The event establishes a measured-boot/TPM attestation health-check failure. Additional evidence is required to determine the exact failed component.

FINDING 02

DistributedCOM Event 10016

DOCUMENTED

Observation: The Windows System log recorded DistributedCOM Event ID 10016 involving the NETWORK SERVICE account and a DCOM Local Activation permission.

Evidence: System Event Log entry containing the CLSID and APPID.

Assessment: The event represents a DCOM permission warning. The event alone does not establish malicious activity.

18 / CONCLUSION

Conclusion

The Windows cybersecurity laboratory demonstrates how a security analyst can combine system configuration, Windows event logging, Sysmon, PowerShell logging, security controls and evidence handling into a structured defensive workflow.

Windows Event Viewer provides the basic event-monitoring capability, while Sysmon can provide additional system telemetry. PowerShell logging provides further visibility into administrative and scripting activity.

Windows hardening complements monitoring by reducing unnecessary exposure and strengthening security controls.

The TPM-WMI Event 1040 and DistributedCOM Event 10016 observed on the laboratory computer demonstrate why individual Windows events should be investigated in context. An event should be documented, correlated with related evidence, and investigated before drawing conclusions about its significance.
